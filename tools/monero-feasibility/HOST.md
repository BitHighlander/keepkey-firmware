# Official CLI/RPC host and funded emulator test

The host stack is official Monero **v0.18.5.4**: `monero-wallet-cli` for manual
inspection, `monero-wallet-rpc` for automated wallet operations, and an offline
`monerod --regtest` daemon. This matches the native emulator's signing-engine
release. The upstream [CLI download](https://www.getmonero.org/downloads/#cli)
includes both the wallet RPC service and daemon.

The original recorded test passed **nine stages and 87 checks**. A stock view-only
wallet scans a confidential funding transaction, imports key images from the
emulator, creates an unsigned transaction, and receives an emulator-signed
transaction accepted and mined by the private daemon. A second transaction
spends only the first transaction's change. Both recipient payments and final
change are independently decrypted and confirmed on the local chain.

The runner now also verifies an explicit `MoneroGetAddress` display request.
Its [live-session run](evidence/2026-11-04-live/README.md) passed 92 checks,
including those address checks and service liveness.

The host wallet contains the emulator's exported private view key and address,
with no emulator spend key. Normal firmware `LoadDevice`, view-export consent,
encrypted key-image sync and complete transaction review are exercised over
the actual HID/protobuf path. The [earlier wallet experiment](WALLET.md)
records the protocol and its bounds.

## Adapter boundary

Stock CLI/RPC does not speak research messages 65000/65001. The new
[host-adapter.cpp](host-adapter.cpp) is a read-only Core-linked executable
using the same pinned release. One JSON request on stdin produces one JSON
response on stdout. Credentials are not passed on the process command line.

- `outputs`: authenticate/decrypt the complete RPC `export_outputs` result
  with the view key and return output ownership metadata in wallet transfer
  order. This supplies the emulator key-image transcript.
- `plan`: authenticate/decrypt the native `unsigned_txset`, recover its masks,
  complete rings and destinations, and match each real input to its exported
  output identity and exact subaddress. Source order and selected-transfer
  order are not assumed identical.

The adapter accepts a primary mainnet-format address and matching private
view key. It refuses spend-key fields, unrelated extra/payment IDs,
incomplete output exports, unsupported container versions, inconsistent
sources/change, zero-value outputs and plans outside the emulator bounds.
Placeholder transaction public keys and an all-zero dummy short payment ID
from the stock wallet are recognized and regenerated/omitted by the signer.

The executable does not open a persistent wallet, connect to a daemon or sign
transactions. Core secret types and selected owned strings are scrubbed;
there is no complete-process memory-erasure claim.

Exact plan comparisons also pass for independently produced encrypted
base-input, subaddress-input and reversed four-input fixtures. Tampered
encrypted containers and spend-key fields are rejected.

The six retained adapter regressions can be rerun without a daemon:

```sh
python3 tools/monero-feasibility/verify_host_adapter.py \
  --host-adapter /private/tmp/monero-host-adapter-new-run/bin/monero-host-adapter \
  --output /private/tmp/monero-host-adapter-check-new-run
```

The emulator returns a raw transaction, not Monero's native `signed_txset`
container. The runner submits those raw bytes directly to its owned private
daemon. Watch-wallet refresh and subsequent key-image import track spent
inputs and change; native wallet pending-transaction metadata is not imported.

## Isolation

`host_emulator.py` creates a fresh daemon database, three disposable RPC
wallets and separate ring databases below an empty output directory. Ports
are chosen locally and bind only to `127.0.0.1`. The daemon runs with
`--offline`, regtest rules, difficulty 1, DNS checkpoints disabled and update
checks disabled. The runner requires a fresh height-1 `fakechain` before
funding. By default, all child processes are terminated on success or failure.
With `--keep-running`, the completed test's emulator and local services stay
available for inspection until SIGINT/SIGTERM; service failure triggers cleanup.

The emulator and recipient use the previously published test fixtures. A
fresh faucet wallet holds only private-chain block rewards. The test mines
100 faucet blocks, sends an ordinary confidential funding payment, and mines
11 blocks after funding and each spend. The wallet RPC processes use the
regtest compatibility option from Monero's own functional harness.

Regtest uses mainnet-format addresses; the wallet has no `--regtest` switch.
The CLI may therefore display `Network type: Mainnet` for these wallet files.
The daemon is an isolated fakechain and no public Monero chain is used.
No physical device is accessed. No existing `emulator.img` or user wallet is
opened.

## Reproduce on the tested macOS ARM host

First build the complete research emulator and independent crypto adapter as
described in [WALLET.md](WALLET.md) and
[INTEROPERABILITY.md](INTEROPERABILITY.md). Keep the four pinned Core/source
dependency archives beside the extracted Core source.

From the firmware root:

```sh
python3 tools/monero-feasibility/prepare_host.py \
  --output /private/tmp/monero-host-tools-new-run

python3 tools/monero-feasibility/build_host.py \
  --source /private/tmp/monero-core-v0.18.5.4 \
  --output /private/tmp/monero-host-adapter-new-run \
  --openssl-root /opt/homebrew/opt/openssl@3

python3 tools/monero-feasibility/host_emulator.py \
  --bin-dir /private/tmp/monero-host-tools-new-run/bin \
  --library /private/tmp/monero-full-wallet-20261104-final2/build/lib/libkkemu.dylib \
  --host-adapter /private/tmp/monero-host-adapter-new-run/bin/monero-host-adapter \
  --core-library /private/tmp/monero-independent-reference-20261104-final/core-reference.dylib \
  --output /private/tmp/monero-host-wallet-new-run
```

The preparation script requires `curl`, `gpg` and `gpgv`. It verifies the
retained binaryFate signature and fingerprint, the exact pinned manifest and
public key, and the downloaded archive hash before extracting the three tools
and license. It writes only to the requested directory and performs no global
installation. `--archive` can reuse a downloaded matching archive. Archive
selection supports macOS and Linux ARM64/x64; the complete native build/run
was tested on macOS ARM64.

`build_host.py --build-dir /private/tmp/monero-core-build-v0.18.5.4` can reuse
the compatible Core compilation cache. The new executable is placed in its
own output directory. All implementation, dependency and executable hashes
are retained in its build report.

Add `--keep-running` to the host runner command to leave the verified session
running. It writes a passing `result.json` before waiting, plus
`live-session.json` with the receive address, loopback RPC URLs, process IDs
and the balance observed at the recorded height. That balance is a snapshot;
use wallet RPC `get_balance` to query it again. Stop the parent PID with
SIGINT/SIGTERM to close the emulator and its services. Stopped/error sessions
are marked unavailable in the live-session file.

The host runner needs permission to bind localhost sockets. It writes a
partial `result.json` and closes its child processes if any stage fails.
All output directories must initially be empty.

After the runner has shut down its RPC processes, the same disposable wallet
can be inspected with the CLI:

```sh
/private/tmp/monero-host-tools-new-run/bin/monero-wallet-cli \
  --offline \
  --wallet-file /private/tmp/monero-host-wallet-new-run/watch-wallet/watch \
  --password '' \
  --shared-ringdb-dir /private/tmp/monero-host-wallet-new-run/cli-ringdb \
  --log-file /private/tmp/monero-host-wallet-new-run/cli.log \
  wallet_info
```

This is an emulator/private-chain integration test. Production GUI support,
the standard streamed hardware-wallet protocol, a reviewed MCU implementation,
broader funded-case coverage and future transaction formats remain open.
