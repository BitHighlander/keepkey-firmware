## Full-diff audit, 2026-09-12

This candidate was audited by reviewing every changed file against its base,
not by re-reading the summaries above. 249 findings were raised across the
three release lines; the 104 rated P1/P2 were each re-checked by three
independent reviewers along separate lines of attack (is it reachable, does it
matter on a shipped release, is it already covered), and 84 survived that.
Everything that survived and applies to this line is fixed at the head below.

Each fix carries a test, and where a control was possible the unfixed code was
built and the test confirmed to fail against it -- a test that passes either
way is recorded as such in the file rather than counted as coverage.

Findings on this line are listed with their resolution in `audit-units/`.
The load-bearing ones for a reader of this receipt:

- cipher recovery committed the EMPTY mnemonic when a ceremony was driven with separators only -- shared with the other two lines and proven end to end against a control build
- a bitcoin-only-locked device refused settings writes only inside storage_commit(), which returns void: ChangePin, ChangeWipeCode, ApplySettings and ApplyPolicies took the user through their confirmations and reported success while nothing was written
- the THORChain deposit decoder was not pinned to a router, so deposit-shaped calldata to any contract inherited the clear-sign UX and skipped the AdvancedMode gate; the native amount screen showed the ABI word rather than msg.value
- the XRP ceiling was 1e6 too low and refused payments shipped firmware signed correctly; CACAO deposits rendered at zero decimals
- the commit CRC covered 642 of the 643 words of the V17 record, leaving the last byte of the encrypted secret outside write verification, while a unit test asserted the opposite
- 'Maximum priority fee' could be below what the Solana runtime charges, because the derived compute-unit limit gave the ComputeBudget instructions nothing (SIMD-0170 allocates them 3,000 each)
- auto-lock measured wall-clock rather than idleness and tore down live ceremonies
- this line was missing the 16 KiB runtime-SRAM link-time gate the other two carry

A second pass then re-read the P3s that the first pass had triaged rather than
re-checked, because "read and judged not to warrant a change" is a weaker
claim than the rest of this receipt makes. Five were real and are now fixed on
this line: a derived private key was left in the shared scratch on two error
exits of the Ethereum transfer path; the RNG health gate read the hardware
fault latch only before a draw, so a fault latching mid-draw was noticed after
those bytes had been handed out; the multisig sighash scratch was one byte
short of the largest signature nanopb can decode; the transfer amount screen
took the Wanchain ticker from a static the transfer path had not set; and
tiny-json defined a global literally named `errno` and declared it in a header.
The rest were verified at head -- some already fixed by another finding's
change, some unreachable -- and `audit-units/` records which.

Two defects were found in the audit's own work and corrected the same way: a
router pin that refused Maya deposits (CI caught it), and a `const` violation
that only ARM GCC rejects (the emulator's clang accepts it). Local ARM
cross-builds using CI's own base image now cover every variant.
