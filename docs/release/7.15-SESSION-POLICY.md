# F02: session-only AdvancedMode

Extracted behavior from alpha 91af1cfc8ee3936ae3df30e227fe1bf8fce4168b,
onto F01 e57afe4f6. This is the policy prerequisite for runtime provider trust;
provider keys, metadata parsing and transaction screens arrive in later units.

- Both V11 and V16 plaintext writers leave retired bit 12 clear.
- Both readers ignore that bit, including upgrade records already carrying it.
- Legacy named policies are replaced with canonical defaults: an attacker must
  not put an enabled AdvancedMode entry ahead of the canonical entry.
- Lock teardown clears AdvancedMode. Soft Initialize preserves the current
  opt-in because hosts routinely initialize before operations. Experimental
  policy behavior is retained.
- Existing ApplyPolicies on-device confirmation remains the authorization path;
  no protocol, flash-layout/version or key-derivation change is introduced.

Four regressions fail on the predecessor and pass after extraction. The legacy
upgrade test is updated to expect canonical ShapeShift defaults, consistent with
later storage readers. The full local native suite passes (149 firmware,
18 board, 4 crypto). Final-head ARM/emulator CI and Copilot are required before
staging acceptance. Physical release acceptance is not claimed.
