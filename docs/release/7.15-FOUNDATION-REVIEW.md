## Versioned storage buffer capacities

The V11 helpers accepted 852 bytes while copying ciphertext through offset
468 + sizeof(encrypted_sec); V16/V17 used offset 1501 with the same legacy
minimum. Their metadata wrappers also passed 852 regardless of the supplied
capacity. All six full-format helpers now reject capacities below the bytes they
actually access, and wrappers pass len minus the 44-byte metadata prefix.
Offsets and ciphertext contents are unchanged. Twenty-five local storage tests
pass, including full-format round-trip, short-input no-mutation and output
canaries at the required capacity. This does not by itself resolve the separate
native emulator restart assertion.

## Signed-char storage decoding (native restart reproduction)

The old native test image asserted after restart with an empty ciphertext and
zero secret fingerprint but serialized flags `0xffffffc0`. `read_u32_le` promoted
signed `char` bytes directly to uint32_t. The mandatory policy bit 7 therefore
sign-extended while V17 amended its flags, falsely setting the secret-fingerprint
and mnemonic flags. This is a host portability defect; ARM behavior must not be
inferred from the native compiler's plain-char signedness.

The reader now interprets bytes as uint8_t before widening. The new round-trip
regression failed before the fix (six incorrect integer/flag assertions) and
passes after it. All assembled native suites pass. A newly wiped emulator image
now survives graceful restart and reports uninitialized. The old image remains
preserved as corrupt test evidence; this change does not repair already-corrupt
images or claim a new storage format.
