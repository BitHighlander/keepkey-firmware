this stack merges into fork develop; human release review is not a prerequisite
to authoring the stack. The objective is the 7.14.2 foundation plus a coherent,
tested extraction of alpha 7.15 functionality, ready for upstream review.

## F04 additive EVM context (draft)

Branch `release/715-04-evm-context` builds on F03. It extracts metadata and
user-confirmed signer-loading handlers from `66b42d02`, registering their wire
messages with bounded nanopb storage. Protocol `4862e5c` is the narrow
LoadClearsignSigner extraction from `8545cd5b` atop audited `f2c3c005`.

Provider context adds confirmation screens without changing the existing
amount, contract, or raw-calldata approval decisions. Cancellation aborts;
nonmatching metadata falls back. Metadata is cleared after the additive review
and on abort. Signer replacement or metadata injection during streaming aborts
that signing session. No host capability is inferred from a version bump.

Local firmware/board/crypto suites pass after this integration. Local generation
uses Python 3.10 and the pinned nanopb 0.3.9.4 generator explicitly (the local
Ninja command override corrects plugin selection; it is not a repository change).
Handler-level consent/cancellation/midstream-injection tests, ARM/host CI,
protocol review and final-head Copilot review remain required. This is a draft,
not an accepted feature or completed stack.

F04 handler validation now includes 10 passing tests compiling the production
metadata handlers with observable confirmation, transport, authentication and
streaming boundaries. They cover store-after-consent ordering, cancellation,
persistence rejection, uint32 slot overflow, AdvancedMode, locked/uninitialized
states, malformed icon encoding, and metadata/signer injection while streaming.
Provider key and icon validation use the actual engine functions. These tests do
not exercise physical buttons, the real PIN ceremony or streaming internals.
All three local suites pass. End-to-end additive-screen/fallback integration,
ARM CI and final-head review remain outstanding.

## F05 transaction-bound Solana account context (draft)

Branch `release/715-05-solana-context` builds on F04. It extracts the existing
`66b42d02` ordered-account attestation verifier and additive provider/account
confirmation block. Protocol `7eeb039` adds only account-list fields 5–7 on top
of F04's protocol branch. The existing AdvancedMode and blind-sign warnings
remain mandatory. Invalid attestations produce the ordinary fallback review;
cancellation at an added screen aborts.

The signed preimage is domain-separated and commits to SHA256(raw transaction),
the little-endian account count and every account in order. Regression coverage
verifies a real signature and rejects changed transaction bytes, substituted or
reordered accounts, changed count, oversized list, slot 256 and revoked signer.
All three local suites pass. Parser compatibility with v0 external account
indices, end-to-end screen/cancellation tests, ARM resource validation and
final-head Copilot review remain required before acceptance. No whole Solana
parser replacement was imported; existing audited fee checks are preserved.
