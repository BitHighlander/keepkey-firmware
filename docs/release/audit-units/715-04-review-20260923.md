## 3. Current-source reconciliation and security findings

| Finding | Sensitive signed state and observer | Path, assertion, falsification, disposition |
| --- | --- | --- |
| S04-1, TRON memo tail hidden | `raw_data.data` memo bytes originate in the host's `TronSignTx.raw_tx`, are serialized into the signed transaction, and must be disclosed in full to the person on the device before signing. Applies to regular firmware during TRON signing; Bitcoin-only has no TRON handler. A byte-count summary, truncated line, or hidden binary tail is forbidden. | The original adjacent diff used one unpaged `confirm` for up to 114 printable bytes and only “Data attached (N bytes)” for binary/long memos. The repair calls `confirm_bytes` on `parsed.memo` and `parsed.memo_len`, which escapes and pages all bytes and requires final-page hold. `Tron.LongBinaryMemoRequiresApprovalOfEveryPage` exercises binary paging; `Tron.RejectingFinalMemoPageCancelsSignHandler` exercises the parsed raw-data path and final-page refusal through `fsm_msgTronSignTx`. Both negative paths check cancellation, and the handler test checks cleared key scratch and no leftover approvals. **Fixed; 25/25 TRON native tests pass locally.** |
| S04-2, MayaChain asset removed | `send.denom`/default `cacao` is the asset serialized into the signing JSON; a person on the device must see it. Applies to regular firmware during MayaChain send signing. The single amount/recipient layout can clip a long denomination; a clipped tail is forbidden. | Original adjacent diff deleted the independent Asset confirmation. The repair calls `confirm_bytes("Asset", coin_denom, strlen(coin_denom))` after amount/recipient approval and aborts on refusal. `Mayachain.RejectingAssetScreenAbortsSendHandler` supplies a 68-character denom to `fsm_msgMayachainMsgAck`, accepts amount/recipient, rejects Asset, and checks cancelled/aborted state and no leftover approvals. **Fixed; 12/12 MayaChain native tests pass locally.** |
