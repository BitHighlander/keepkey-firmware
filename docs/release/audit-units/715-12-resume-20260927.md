## Finite repair batch: S12-01

All three supported Hive signing operations accept an explicitly malformed
chain ID and silently replace it with mainnet. The host can send any short
bytes field through nanopb (maximum 32), including a present empty value.
The handlers currently show consent before this substitution. This is an
inherited validation defect, not evidence of a demonstrated fund theft.

Contract: omitted chain ID retains the mainnet default; a present chain ID
must contain exactly 32 bytes. Reject other lengths before consent or key
derivation and independently at each signing entry point. Preserve exact-length
custom domains; their disclosure/policy remains a separate audit question.

Consumer inspection: hdwallet-keepkey's `hiveSignTx`, `hiveSignAccountCreate`
and `hiveSignAccountUpdate` omit the field when `chainId` is undefined and
otherwise forward the supplied bytes. Existing Python callers supply 32-byte
mainnet IDs. No protocol bound or dependency pin change is needed.

Checks: native all-three-operation rejection for lengths 0 through 31;
omission/explicit-mainnet equivalence; valid custom-domain preservation;
actual transport rejection before ButtonRequest and valid retry. Run the new
regressions on the old implementation as a negative control, then on the repair.
