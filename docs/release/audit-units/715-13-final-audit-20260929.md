## 3. Audit round

Two independent read-only source audits covered the merged diff. The product audit found no serious defect and no merge-interaction defect: wallet creation refuses before any confirmation or arming under the merged guards, the entropy budget cannot underflow and a refused request spends nothing, empty recovery input is rejected, and the layout signature change has a single caller. The tests-and-gates audit found no test that expects a message or count the merged code does not produce, and no gate inconsistency. It named the one place CI could go red: removing two waivers makes previously skipped Python tests mandatory.

Known limits, all documented Block 13 policy and left unchanged:

- Osmosis send amounts are capped at uint64 max. The pinned Python test requires exactly this, but for 18-decimal denominations it limits a send to about 18.4 tokens.
- Accepted workflow starts renew the auto-lock deadline, so a connected host can keep an already-unlocked device from auto-locking by sending valid starts. Ethereum ClearSign and Bitcoin already behave this way in the base.
- `recovery_delete_character` on an empty mnemonic re-rolls the cipher (low severity, unchanged behaviour).
