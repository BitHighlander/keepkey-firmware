## 3. Audit round

Two independent read-only source audits covered the merged diff. The product audit found no serious defect and no merge-interaction defect: wallet creation refuses before any confirmation or arming under the merged guards, the entropy budget cannot underflow and a refused request spends nothing, empty recovery input is rejected, and the layout signature change has a single caller. The tests-and-gates audit found no test that expects a message or count the merged code does not produce, and no gate inconsistency. It named the one place CI could go red: removing two waivers makes previously skipped Python tests mandatory.

Decisions on the audit's three observations:

- **Osmosis send cap: fixed** (`a1941dfa8`, test corrected in `77e2d752f`). The uint64 bound was applied to every denomination, so an 18-decimal IBC or factory asset could not be sent above about 18.4 tokens. It now applies to `uosmo` only. The wire already limits the amount to 32 digits and the denomination to 68 characters, so the worst-case screen string is 101 bytes in a 128-byte buffer, and the signer hashes the amount in segments with no fixed buffer. The first hosted run of the new test failed with `ActionCancelled` because a wide amount beside a long denomination paginates over several confirmation screens and only one approval was preloaded; the amount had passed validation and reached review, so the test was corrected, not the product change.
- **Auto-lock renewal by valid starts: tracked, not changed** (issue #891). Accepted workflow starts renew the deadline, so a connected host can keep an already-unlocked device from auto-locking by sending valid starts. This is Block 13's tested design (invalid starts, declined confirmations and idle polling cannot renew), it is needed so a workflow begun just before the deadline can finish, and Ethereum ClearSign and Bitcoin already behave this way in the base. Fixing it means splitting start and progress renewals across about 15 call sites and re-testing, so it needs the owner's decision.
- **Recovery cipher re-roll on an empty delete: not a defect, unchanged.** Every `CharacterAck` gets a freshly scrambled cipher and a `CharacterRequest` reply; that is how the scheme works, and the mapping is never sent to the host. The audit's suggested redraw would send no `CharacterRequest` and hang the host.
