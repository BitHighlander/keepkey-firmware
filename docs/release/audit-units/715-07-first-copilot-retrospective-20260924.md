## What went wrong

The failure was substantive. Reviewed calldata was not committed to the bytes eventually signed, a certified typed-data program could omit later display fields, and nested fixed-array validation was wrong. Header guards, direct-call range validation and the release narrative also escaped preflight. Parser unit coverage and successful links did not establish the complete signing contract.

The implementation distributed authority over several passes: authenticated definition replay, ABI or typed-data traversal, UI confirmation, and final signing. Tests validated each piece but did not prove that the values and schemas stayed identical between pieces. They also did not exercise a real signed catalog through every host/device continuation and cancellation path. That gap explains both the review's calldata finding and the additional schema, ownership, domain and identity defects found while repairing it.

The first request reviewed a historical branch while the predecessor audit was still changing. That made its result useful for discovery but insufficient for acceptance. Reconciliation later introduced a concrete interaction failure: Stack 06's stricter dispatcher aborted the new Stack 07 continuation messages. The ordinary host suite passed while six of seven new authenticated protocol tests failed. Only running the complete new workflow on the integrated predecessor exposed it. Those tests are now registered in the repository CI runner.

There was also an earlier wrong-PR review request during the Stack 05/07 transition. That was an execution error, not Stack 07 coverage. Before any future authorized request, record the explicit PR number, immutable head, actual base, claim owner and code-bearing diff together. This review budget does not authorize an automatic retry.

The primary process failure was a missing **successful final replay** fixture. The old negative case changed the fourth pass and expected refusal; it passed without proving that an unchanged fourth pass could ever reach the signer. The state name CALLDATA hid the distinction between verification and signing. Future cross-phase tests must include a positive signature equality case and a mutation case for every replay transition, with the same nonzero payload.

The second gap was session-boundary reasoning. `erc7730_workflow_abort()` intentionally leaves preload untouched when the workflow is IDLE so a newly loaded definition survives until its next signing request. That is valid at the transaction entry but unsafe after a failed typed-data start. The repair clears the catalog at the specific failed terminal exits, and the tests immediately start another ordinary request to catch stale state. The related review comment about cleanup after the END display was investigated separately with a two-field replay rather than classified by proximity.

The third gap was a zero-leaf consent path. The schema and hash are valid for an empty primary struct, so a parser rejection would conflate protocol validity with consent. A final visible confirmation gives the user an explicit decision without altering canonical hashing. The negative test requires a Failure on decline, and the positive test requires a signature only after acceptance.

The two `warn_unused_result` findings and duplicate scrub are small but legitimate review regressions. They were repaired because they are simple to verify and improve future caller discipline. No second-review P1 is accepted as minor. The repaired head requires a fresh exact-head CI result and review-thread dispositions before a third review could be proposed to the owner.
