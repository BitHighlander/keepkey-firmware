## Findings and policy disposition

### S01-01 — unrelated host traffic extends an active session's auto-lock

Severity: P2 policy/security review, fixed locally after owner decision. Changed lines:
`lib/firmware/fsm.c:328-330` and `lib/firmware/home_sm.c:193-197` at the PR
head. `fsm_usb_rx()` calls `note_host_activity()` before parsing or dispatching
every frame. While `home_state == AWAY_FROM_HOME`, that clears the idle timer
regardless of message type, validity or whether it advances the signing/setup
workflow. A host that periodically sends `GetFeatures` (or malformed frames)
can keep an otherwise stalled signing session from reaching the configured
auto-lock delay. The new tests in `unittests/firmware/fsm.cpp` call
`note_host_activity()` directly and prove only that any call extends the timer;
they do not exercise unrelated frames through USB or set a policy for them.
The same concern was recorded in the 2026-09-13 re-audit handoff for the
candidate line. On 2026-09-23 the owner specified that only active workflow
progress should extend the timer. The local patch removes the pre-dispatch
reset and calls `note_host_activity()` after a continuation request is encoded
and sent. It names the supported streamed request types; `Features`, failures,
and other unrelated responses are excluded. The new regression sends a valid
`GetFeatures` packet through the parser during a Bitcoin signing wait and
proves auto-lock still fires, while a sent `TxRequest` extends the wait. These
tests passed in a full local Docker native run: 328 firmware, 20 board, 18
crypto tests. A compose `up` first failed before tests because local port 5000
was occupied; `docker compose run --no-deps firmware-unit` on the same built
image completed with exit code 0. The original exact-head hosted CI predates
this patch. The Bitcoin-only image built separately with
`docker-compose.bitcoin-only.yml`, then its native run also passed: 115
firmware, 20 board, 18 crypto tests.

### S01-02 — emulator progress animation stopped while polling the host

Severity: P3, fixed locally in this audit branch. The PR replaced the tail of
`lib/board/udp.c:usbPoll()` with a buffer scrub and removed its call to
`layout_animate_poll()`. The hardware USB poll still calls the animation pump;
without the emulator call, a queued Zcash progress animation freezes whenever
the emulator is waiting for host proof generation. The local patch restores the
animation call after the buffer scrub. A new board test arms the real progress
trickle, calls emulator `usbPoll()`, and requires a display refresh; it passed
in the local Docker run above. Physical Zcash signing is still a release gate.
