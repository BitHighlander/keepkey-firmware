## Sixth review (5314077647) on `5e2e3d16b`

Verdict **Needs a closer look** (Lite). It had one finding and listed the fifth-review finding as resolved.

| Comment | Disposition |
| --- | --- |
| `4101637522` | **Fixed.** 00b's delete resync rebuilt `coded_word` from the current `cipher`, on the stated assumption that the session cipher is fixed. That assumption is false: `next_character()` re-scrambles the cipher before every character. After a backspace, `coded_word` therefore held letters the user never typed. It feeds the "typing the seed without the cipher" heuristic, which could abort a valid recovery. Now `coded_word` keeps only the characters actually typed and is truncated on delete. When a delete steps back over a space into a finished word, whose typed characters were discarded at the boundary, the coded prefix is marked unknown and the heuristic is skipped for that word. It is never guessed. The flag clears at every word boundary, at mnemonic start and on reset. |
| Same-class audit | The only other use of `cipher` decodes the character that was just typed, under the mapping that was just displayed, which is correct. The DebugLink read is test-only. The per-word BIP39 validation already reads `decoded_word`, which is resynced from the mnemonic. |

Regression: `Recovery.DeleteKeepsTypedCipherCharactersNotTheCurrentMapping`, via the firmware-unit probe. It uses an identity cipher, under which the old reconstruction yields `ab` instead of the typed `qw`. It also covers crossing a word boundary, and an unknown prefix that persists until the word is emptied. Local Docker was unavailable and local cppcheck 2.20 failed its control (it did not reproduce CI's earlier finding), so **hosted CI is the qualification for this change.**
