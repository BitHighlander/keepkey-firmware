### C-2 bootloader boundary

The owner retained “No bootloader changes” as a hard 7.15 release constraint.
The direct bootloader source file now matches pre-foundation commit
`fc1e93746132553ad98ed60f4847c8d770732bf9`; the shared
`signatures_ok()` implementation matches accepted 00a. The F3 double-hash and
infective signature-verification change is withdrawn from 00b, since that
shared function is called by the bootloader. A manual opt-in build still
produces a different bootloader binary from the pre-foundation build
(`2142a51c…` versus `a831baf0…`, SHA-256) because other shared libraries have
changed. Therefore the default release build disables bootloader, updater and
bootstrap targets. Clean full and Bitcoin-only ARM builds produced none of
those artifacts; CI now fails if any are present. The opt-in build is outside
the 7.15 release and must not be packaged as its bootloader.
