# 7.15 alpha delta audit

This ledger compares the fixed alpha source `78c54c316` with the staged 7.15
release. It records policy decisions; commit equivalence is not expected where
the release implementation was adapted to preserve its audit boundaries.

| Alpha change | 7.15 disposition | Evidence / boundary |
| --- | --- | --- |
| #783–#802 ERC-7730 display VM and formatter series | Included, adapted | Firmware stacks 7–8 (#837–#838), including the #820 CI/correctness follow-ups and #823 calldata binding. All entry points require AdvancedMode. |

The release advances only along the canonical python-keepkey
`reconcile/upstream-sync` ancestry. Stack 9 pins its version-gated EOS coverage;
stack 11 advances to PR #226 for the matching Solana capability gate. The same
companion line continues to support older firmware through feature/version
gating rather than release-specific branches.

## Executable policy lock

- Clearing runtime signers leaves every metadata key slot unresolved.
- Metadata processing and generic/runtime attestation verification are inert
  when AdvancedMode is disabled.
- Runtime identities receive an explicit identity presentation; the display
  code fails closed if metadata ever arrives from a non-runtime signer source.
- ERC-7730 and Solana schema entry points independently require AdvancedMode,
  so a future parser or transport change cannot bypass the signer policy.

## Deferred alpha-only trust features

Root certificates, delegated certificates, certified Solana lookup-table
proofs, certified token definitions, and Portals/dynamic certified decoders are
not part of 7.15. They require a separately authorized trust-policy release.

The release therefore carries the alpha decoding and display capability while
deliberately excluding alpha's firmware-owned trust root and every feature that
depends on it.
