# 7.14.2 signing hardening

This point-release work is based on `release/7.14.2` at
`bc34c63ada27fd713dfd1a3bef8554c033a87913`. It uses focused backports rather
than taking the broad rc17 change as a unit.

## Threat model and severity

These are malicious-host display and policy failures against an initialized,
unlocked, PIN-authenticated device. Signing still requires the user to complete
the on-device confirmations. They are not unattended host-signing defects, but
they are P1 blockers because the display or AdvancedMode policy is not bound to
what the device signs.

## Point-release remediation

| Surface | Remediation |
|---|---|
| Bitcoin-family `SignMessage` | Review the complete length-delimited payload before signing. |
| Ethereum and TRON `SignMessage` | Review every signed byte rather than a prefix. |
| Ethereum EIP-712 and TRON TIP-712 precomputed hashes | Require AdvancedMode, validate digest lengths, and show an explicit blind-signing warning before the existing address/hash confirmations. |
| Structured Ethereum EIP-712 | Restore the released encoder behind a fail-closed preflight for flat structs of canonical atomic values. Review every field name, declared type, value, and primary type exactly; bind the domain and message calls to the same raw schema and signer. Arrays, nested structs, Unicode escapes, and integers outside the encoder's proven 64-bit range remain unsupported. |
| EOS unknown actions | Require AdvancedMode and include `EOS_NewAccount` in the structured-action allowlist. The gate does not depend on `review()`, which discards `confirm_helper()`'s result on this line. |
| Exact signed-content review | Add an exact-byte OLED pager. Spaces, backslashes, controls, and non-ASCII bytes are rendered as `\xNN`; page boundaries are calculated from the actual OLED font metrics; every page requires confirmation. This closes the #428 leading-whitespace and clipped-suffix pattern without changing unrelated generic dialogs. |
| Binance transfers | Validate the complete transfer shape, positive/equal amounts, canonical bounded denomination grammar, message/session state, and serialization results before signing. |
| Cosmos IBC | Retain receiver disclosure, require the signed `uatom` denomination, and review sender/receiver through the exact-byte pager. |
| Generic Tendermint | Bind every ACK to the initialized protocol and the original chain name, denomination, and message-type prefix; use those bound values for display and hashing. |
| Binance, Cosmos, Osmosis, and generic Tendermint memos | Review the complete memo with the exact-byte pager. |

The EIP-712 `%ld`/`uint32_t *` issue is treated as P3, not P2. The replacement
accepts only canonical unsigned decimal input with checked `uint32_t` overflow.
The discarded token lookup was removed.

The reported 65-byte `strncat` bound is not an overflow: 20 prefix bytes, 44
appended bytes, and the NUL fit exactly. It is not tracked as a bounds defect.
The host-controlled-type/display divergence is covered by a bounded validator
in front of the existing encoder. It requires exact root shapes, one value for
every unique declared field, canonical atomic types and values, and an exact
primary type. Unsupported shapes fail before hashing or display and can still
be signed explicitly through the AdvancedMode typed-hash endpoint.

## Regression evidence

- Pinned `kktech/firmware:v15` emulator build: passed.
- Board unit tests: 9/9 passed, including exact rendering of whitespace,
  newlines, backslashes, embedded NULs, and an oversized whitespace-prefix
  payload whose suffix must appear on a later page.
- Firmware unit tests: 84/84 passed, including canonical structured EIP-712
  domains/messages and rejection of nested types, arrays, duplicate/extra
  fields, malformed bytes, non-canonical integers, and unsupported Unicode
  escapes.
- Emulator integration: a flat `Permit` payload produced domain and message
  hashes matching independent Viem vectors and signed successfully; a second
  call with a different schema was refused by the session binding.
- Crypto unit tests: 4/4 passed.
- Release-style `arm-none-eabi` build: `firmware.keepkey.elf` linked
  successfully.
- Full-tree cppcheck using the CI arguments: zero findings.

## Remaining release gates

This patch set is not sufficient to tag 7.14.2. Before release:

1. Resolve #429's setup transaction/rollback behavior.
2. Triage every remaining audit finding and run another adversarial comparison
   over the complete candidate.
3. Independently re-exploit the fixed paths, including cancellation and all
   exact-pager boundaries.
4. Verify every changed confirmation path on physical OLED hardware and retain
   visual evidence.
5. Run the complete CI and integration suite, preserve storage across a signed
   upgrade, and only then update the version/tag and draft advisories.
